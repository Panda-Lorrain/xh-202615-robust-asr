## 2. timing 语义（关键，决定怎么跑、报哪个数）

`submit_infer.py` 产出 `timing.json` + `result.json`，两个 RTF 口径都要看：

| 字段 | 定义 | 说明 |
|---|---|---|
| `overall_rtf` | `total_wall_sec / total_audio_sec` | **端到端**：含 SE + 切 timeline + ASR 转写 + 模型加载（全量跑被 n_utt 摊薄）。**评委复现将看到的量级 → 主报告值** |
| `duration_infer_rtf` | `sum(per-utt infer_sec) / total_audio_sec` | **纯推理**（不含模型加载）。⚠️ **qwen/firered 后端低估**：`infer_sec`（`enroll_infer.py:382`）只含切 timeline，ASR 转写在循环外 subprocess（`:388`），未计入 → 此值漏报 Qwen3-ASR 转写时间 |
| `result.json[].peak_mem_mib` | 每条峰值显存 | 内存腿用 `max()`。旧 result 可能无此字段（`enroll_infer:383` 才产） |

**实测铁律**：
1. **必须跑全量**（pos 1364 条）：`overall_rtf` 含一次模型加载，全量才摊薄；小样本 RTF 虚高。
2. **报 `overall_rtf`**（端到端诚实），勿报 `duration_infer_rtf`（qwen 低估）。
3. **batch=1 语义**：submit_infer 每条独立推理（`enroll_infer:383 batch_size=1`），符合官方 batch=1 计时口径。
4. **vanilla 后端的 `infer_sec` 含 vanilla 转写**（循环内 generate），故 vanilla `duration_infer_rtf` 不低估；仅 qwen/firered 低估。

## 6. 效率腿分数区间估算（task3）

### 6.1 本机 4060 baseline（实测真实数据）
| 后端 | overall_rtf | duration_infer_rtf | 来源 |
|---|---|---|---|
| vanilla | **0.224**（含 SE） | 0.144 | `out_pos_vanilla_full/timing.json`（1364 条全量，本 session 实测） |
| qwen | 待 L20 实测 | 待 L20 实测 | ⚠️ 见下注（0.289 曾误标为 RTF，已澄清） |

phases 拆分（vanilla 4060 全量，总音频 3498s / 总墙钟 783s）：
- `noise_classify` 7.15s（2%）/ `se` 222s（**28%**）/ `enroll_diar_dicow` 524s（67%，含转写）

> **SE 占 28% 是大头**。qwen 路线同样走 SE（`submit_infer` 默认 `use_se=True`）。若 SE 对 qwen 转写无增益，可试 `--no-se` 砍 28% 时间（需验证 CER 不退化，留作优化项）。
>
> ⚠️ **qwen "0.289" 口径澄清（2026-07-15 审查 medium，重要）**：交接文档 / `qwen_official_cer_workpoints.json:89` 的 "Qwen3 RTF0.289@4060" 实为 `poc_qwen_asr.py:88` 的 **"Qwen3-ASR 转写 ≈ 0.289 秒/条（仅转写，不含 enroll/diar/cut/SE/加载）"**——是「秒/条」被误当无量纲 RTF，且放进 duration_infer_rtf 列也错（qwen 该口径本就排除转写，应 < vanilla 0.144）。qwen 真实 `overall_rtf`/`duration_infer_rtf` **本机从未实测**（无 `out_pos_qwen_full/timing.json`），待 L20 实测。故 §6.2 qwen 外推仅粗估，**答辩勿直接引 "0.289" 作 RTF**。

### 6.2 L20/L40 外推
- **算力比（4060→L40）**：L40（AD102，稠密 FP16 ~90 TFLOPS）vs 4060（AD107，~23 TFLOPS）≈ **3.9×**。RTF 加速受 CPU/diar/IO 瓶颈非线性，保守取 **3–4×**。
- **⚠️ L20 ≠ L40（2026-07-23 勘误，纠正早期 agent 把两者等同的幻觉）**：L20 与 L40 同为 AD102/Ada，但 **L20 是中国特供精简版**（CUDA 核心 11748 vs L40 的 18176，砍了部分 tensor/NVENC/光追），**L20 算力约为 L40 的 65%**（L20 慢约 1/3）。故本节下文的 ~0.06–0.08 是 **L40 口径**；**外推官方 L20 须再 ×1.5 → ~0.09–0.12**（即 L20 vs 4060 ≈ 2.5×）。**租到真 L20 直接用最准、答辩最硬**；只有租到 L40 时才需此 ×1.5 折算。严格映射（RTF≤0.1）下 L20 卡边界，故效率腿区间**诚实宜报 18–19/20**（而非稳 19–20）；宽松/中等映射仍满分。
- **qwen**（粗估，待 L20 实测）：shared pipeline（SE 222 + enroll/diar/cut ~260 + nc 7 ≈ 489s）+ Qwen3 转写（0.289s/条 × 1364 ≈ 394s）≈ 883s → 4060 `overall_rtf ≈ 0.25`（qwen 转写慢于 vanilla，故略高于 vanilla 0.224）→ L40 `~0.063–0.084`。此为把「转写 0.289s/条」（非 RTF，见 §6.1 注）正确换算后的估算。
- **vanilla**：0.224@4060 → L40 `overall_rtf ~0.056–0.075`。
- **显存**：qwen 路线 peak = DiariZen WavLM-Large（~1.2GB）+ Qwen3-ASR-1.7B bf16（~3.4GB）+ Whisper fe（轻量）+ 激活 < **8GiB**，远低于 46GiB cap。

### 6.3 区间结论
| 腿 | 估值 | 依据 |
|---|---|---|
| 时间腿 /10 | **9–10** | L20 `overall_rtf ~0.06–0.10`（vanilla 0.224 扎实外推 + qwen 估算），宽松/中等/严格/阶梯映射均满分；极严（RTF≤0.1）边界 9–10 |
| 内存腿 /10 | **10** | peak <8GiB / 46GiB cap，所有映射满分 |
| **效率腿 /20** | **19–20**（保守 18） | |

**合计初评总分**（w1=w2=w_eff 假设）：**CER 16.26 + RR 36.20 + 效率 19–20 ≈ 71.5–72.5 / 100**。

> 真实数字以 L20 实测 `overall_rtf` 为准（L40 近似需 ×1.5）；本估算用于答辩「效率腿预计近满分」+ 决策「值不值得租机器」（结论：值得，唯一可搏且近天花板）。

## 8. 待主办方确认（影响最终值，memory `official-scoring-spec`）
1. 排名公式权重 `w1`/`w2`/`w_eff`（RR-heavy 则 thr 上移；效率权重决定投入产出）。

## 9. 答辩弹药
- **「CER 减半 + 效率近满分」**：vanilla 反 cascaded 把 CER 1.25→0.664 减半，qwen 进一步 0.3436；效率腿 vanilla 4060 `overall_rtf 0.224`（含 SE），L20 外推 <0.1，时间腿近满分。
- **诚实双口径**：主动报告 `overall_rtf`（端到端）vs `duration_infer_rtf`（纯推理），并指出 qwen 后端低估点——工程诚实度。
- **工程优化**：Gap3 批量化（模型加载 1 次，enroll 39→11s）+ 跨平台 Linux-ready（本 session）+ batch=1 计时内置（`timing.json` schema 对齐官方）+ 可复现性（seed 透传 + run-twice delta=0）。
- **诚实归因**：CER 死区 112 条是 babble 摧毁 mel 物理极限（`spk-oracle-poc`），qwen/vanilla 都救不了 → CER 腿 16.26 近天花板，效率腿是唯一可搏增量。
