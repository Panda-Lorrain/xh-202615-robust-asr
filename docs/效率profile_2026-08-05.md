# 效率腿 Profile（2026-08-05，4060 首跑）

> 对应 AGENT_HANDOFF_2026-08-05 §4.3。目的：拆 submit_infer 4 阶段耗时，定位瓶颈，指导 Phase 4 优化选型。
> 裁决纪律：本文数字为 4060（AD107）相对测量，**绝对 RTF 不可外推 L20（AD102）**，仅用于阶段占比 + 相对改善。

## 一、方法

- **配置**：当前提交线 = `run_baodi.sh pos 0.27` 等价 flag —— qwen 后端 + `--no-se` + `--no-llm` + `--content-gate` + `--strategy sim_only --sim-thr 0.27`，**batch=1**（提交口径），N=100 pos。
- **插桩**（本轮新加，3 点）：
  - `qwen_asr_backend.py` 写 sidecar `_qwen_timing.json` = `{load_sec, transcribe_sec, n_items, n_uid, batch_size}`
  - `enroll_infer.py` 计 enroll 侧模型加载 + 包 qwen 子进程墙钟、读 sidecar 算 overhead
- **4 桶**：A=enroll 模型加载(DiariZen+wespeaker+whisper fe) / B=per-utt wespeaker+diar+cut+落盘(=Σ`infer_sec`) / C=Qwen3 转写 / C'=Qwen3 加载 / D=qwen 子进程启动+IO

## 二、结果（N=100 干净 per-unit 速率 + N=1364 投影）

## 三、瓶颈定位

> **C（Qwen3-ASR 转写）是 RTF 大头**，占可变成本 ~64%，且随切片数放大。Phase 4 优化**主攻 C**，次攻 B。
> 每 slice 0.314s@4060 → L20(~2.5×) 约 0.05-0.08 RTF/slice，与 §4.1「Qwen3 纯 ASR L20 理论 0.05-0.08」自洽。

## 四、⚠️ 两个测量问题（已识别，影响后续实验，已定处理）

### 1. slice 污染（dev-trap，**非生产 bug**）
`qwen_asr_backend.py` 不去重，固定 slice dir `E:/target_slices_qwen/` 跨 run 累积，每轮 `sorted(glob(*.wav))` 全转。本轮实测 C=586.7s 含 1767 个 07-18/19 旧切片 + 100 新（应为 31.4s/100）。
- **per-slice 0.314 仍可靠**（586.7/1867）。
- **生产 L20 全新部署，slice dir 空 → 不受影响**（一次 eval 仅转本轮 1735 切片）。
- **Phase 4 处理**：每个 run 前 `rm -rf E:/target_slices_qwen/*` 清空，保证 C 测在确切 N 切片。
- **待硬化（提交前 checklist）**：submit_infer 应传 per-run slice dir（`<work_dir>/slices`）或 enroll_infer 启动清空，消除 dev-trap。

### 2. stdout 盲点（A/D 只能差减）
`submit_infer._run`（line 122-131）`subprocess.run(capture_output=True)` 成功时丢弃子进程 stdout → `[enroll-profile]`/`[qwen-profile]` print 永不进 log。故 A（enroll 加载）、D（overhead）无法直测，仅得 A+D=40.6s 残差。
- C/C' 靠 sidecar JSON（写磁盘）→ **可靠**；B 靠 result.json infer_sec → **可靠**。
- **Phase 4 不修**：用 sidecar+result+timing 三处磁盘产物读数，不依赖 print。若后续要直测 A/D：改 `_run` 用 `stdout=PIPE`+tee 或 bypass submit_infer 直跑 enroll_infer。
