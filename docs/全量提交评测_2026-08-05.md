## 5. venv 阻塞（hard blocker，无法重跑验证）

### 5.1 阻塞事实

- **主推理 venv `code/.venv` 完全不存在**（memory
  `a-set-is-real-recorded` 2026-08-01 记「本机 venv 坏」）
- `submit_infer.py` 默认 `PY_MAIN = code/.venv/Scripts/python.exe`
  跑 `enroll_infer`（diar + 切 target timeline + sim 拒识），
  该 venv 缺失 → 无法重跑全量推理
- 现存 venv：`.venv_llm` / `code/.venv_qwen`（Qwen3-ASR 专用）/
  `code/.venv_firered` / `code/.venv_realt` / `code/.venv_tse`（07-29
  训 WeSep 用），**无任何单一 venv 能完整跑 enroll_infer**

### 5.2 重建尝试与不可调和冲突（已穷尽快速路径）

enroll_infer 依赖：`torch+cu124` + `speechbrain` + `diarizen`（本地
vendored，`code/DiCoW-inference/DiariZen/`）+ vendored `pyannote-audio`
+ `wespeaker`（通过 `diar._embedding` 复用，非独立包）+ `transformers`
+ `pyarrow`/`zhconv`/`cn2an`/`editdistance`/`toml` 等。

尝试 1：补 `.venv_tse`（有 speechbrain+torchaudio+transformers）→ 装
`zhconv/cn2an/editdistance/pyarrow/toml` 后 enroll_infer import OK，
但装 PyPI `pyannote.audio` 解决 diarizen 依赖时**破坏 venv**：
torch 2.6+cu124 → 2.13+cpu（CUDA 失效）、numpy 1.26 → 2.x、
torchaudio 2.3 → 2.11。

尝试 2：补 `.venv_qwen`（torch 2.6+cu124 cuda True 完好）→ 装
`speechbrain/toml` + vendored pyannote 子包（pyannote.core/database/
metrics/pipeline）+ sortedcontainers/pytorch_lightning/julius/
torch_pitch_shift/primePy 等 ~15 包，逐个补依赖。**最终撞上不可调和
版本冲突**：
- vendored pyannote/diarizen 用 `np.NaN`，要 **numpy<2.0**
  （requirements 声明 numpy==1.26.4）
- `transformers` 4.57.6 用 `np.long`，要 **numpy 2.x**
- 单 venv 无法同时满足 → 必须 diarizen 用一个 venv、Qwen3-ASR 用另一个

这正是原设计双 venv（`code/.venv` enroll_infer + `code/.venv_qwen`
qwen_asr_backend）的原因。主 venv `code/.venv` 缺失 = 不可绕过。

### 5.3 损害记录（需用户知晓，便于恢复）

| venv | 改动 | 当前状态 |
|---|---|---|
| `.venv_tse` | 装 pyannote.audio（破坏）+ zhconv/cn2an/editdistance/pyarrow/toml | **torch 2.13+cpu（CUDA 失效）/ numpy 2.x / torchaudio 2.11**。原本是 07-29 训 WeSep 的 venv，任务已完成归档，但若要复用需重装 torch 2.6.0+cu124（`uv pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124`）+ numpy==1.26.4 |
| `.venv_qwen` | 装 speechbrain/toml + pyannote 子包 + sortedcontainers/pytorch_lightning/julius/torch_pitch_shift/primePy/lightning-utilities/lightning-fabric/tensorboardx/torch-audiomentations/torchmetrics/omegaconf/einops/asteroid-filterbanks/semver（enroll_infer 依赖）；numpy 经降级到 1.26.4 后**已恢复回 2.4.6** | **torch 2.6.0+cu124 cuda True / numpy 2.4.6 / transformers 4.57.6 完好**；`qwen_asr_backend` import 验证通过（Qwen3-ASR 链路未坏）。多装包不影响 Qwen3-ASR 推理，但跑 enroll_infer 会因 numpy 2.x 崩 |

恢复建议：
- `.venv_qwen`：保持现状（Qwen3-ASR 可用），不要再动它跑 enroll_infer
- `.venv_tse`：若需 WeSep 复用，重装 torch+cu124 + numpy 1.26.4
- `code/.venv`：**需按 `code/REPRO_SETUP.md` 重建**（wespeaker/diarizen
  git clone + torch 2.5.1+cu124 + numpy 1.26.4 + transformers 4.42.4
  + 各音频库），是大工程（数小时，含 wespeaker/diarizen 版本调试）

### 5.4 对本报告数字的影响

07-30 全量数据由那时完好的 `code/.venv` 跑出，配置与当前主线完全一致，
同一 run 全量、同一配置、本报告独立重算复现。**venv 阻塞只阻止「再跑
