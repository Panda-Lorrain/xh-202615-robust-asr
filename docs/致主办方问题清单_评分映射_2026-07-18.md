# 致主办方：评分口径确认问题清单（XH-202615）

> 2026-07-18 起草。背景：初评排名公式 `TotalScore = w1*(1−CER) + w2*RR` 已公布（2026-07-08），CER 算法 + 预处理口径已与主办方参考脚本逐行核对一致（NFKC + lower + 去 Unicode P* 标点空白 + 累计池 editdistance）。以下为**直接影响方案选点 / 投入分配**的剩余待确认项，按优先级排序。望答复。

---

## P0 — 直接决定选点，望优先答复

### 1. 排名公式权重 w1 / w2 的具体值
`TotalScore = w1*(1−CER) + w2*RR` 中 w1、w2 各是多少？
- 若 w1 = w2 = 0.4（与 CER40/RR40 一致），则当前统一 thr=0.27 选点定稿。
- 若 RR-heavy（w2 > w1），则 thr 应上移至 0.35–0.40 以换 RR。
- 该值直接决定 pos/neg 拒识阈值的最终选点。

### 2. 效率 20% 的打分范式：绝对阈值 还是 相对排名？
这是**影响最大的一个未确认项**：
- **若绝对阈值**：请公布时间腿（10 分）与内存腿（10 分）的阈值映射公式。例如 RTF ≤ X → 满分，X–Y 区间线性，>Y → 0？
- **若相对排名**（各队相互比较，top X% 满分）：则效率分无绝对天花板，每一 % 的 RTF 优化都换名次。
- 这决定我们是否要在效率腿继续投入工程优化（如模型精度、推理后端调优）。

### 3. RTF / 推理时间的计时口径
"每条语音平均推理时间"是否包含**模型加载时间**？
- batch=1 定义下：含加载 → 报端到端墙钟 / 音频时长；不含 → 报纯推理 / 音频时长。
- 这决定我们提交时 duration 字段报哪个值（端到端诚实 vs 纯推理）。

### 7. A 集初评允许 pos / neg 分别设拒识阈值吗？

## 已确认项（列出供核对，无需再答）

- ✅ CER = (S+I+D)/N，Levenshtein 编辑距离，**字符级**（中文按字），可 >1，per-sample 不封顶。
- ✅ 预处理：`unicodedata.NFKC` + lower + 去所有 Unicode P* 标点和空白；**不繁简归一、不数字归一**（ref"二十六"非"26"）。
- ✅ pos（目标语音）允许被拒，拒 = CER 1.0，无额外惩罚。
- ✅ 排名制（初赛排名进决赛）。
- ✅ batch 默认 1；RTF 按 batch=1 测（大 batch 不加分）。
- ✅ 评测硬件 L20-46G。
- ✅ 数据增广不限。
