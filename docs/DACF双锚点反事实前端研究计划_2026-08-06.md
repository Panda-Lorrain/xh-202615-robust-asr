DACF 不是现有 TSE 再换一个网络，也不是给当前 `max_sim` 再叠一条规则。它要验证的最小命题是：

> 对同一条、逐字节不变的混合音频，只改变 enrollment query，模型能否稳定切换“谁是目标”，并在查询者不在混合中时输出 blank。

固定反事实组必须是：

```text
M(A+B) + enroll(A) -> A / present / activity_A
M(A+B) + enroll(B) -> B / present / activity_B
M(A+B) + enroll(C) -> silence / absent / activity_0
```

当前只允许进行小规模因果证伪，不允许直接扩到 800+ 或租卡训练。骨架通过只代表接口和梯度链自洽，不代表 CER 有提升。

## 1. 为什么这条路线值得押

当前提交 CER 的主要损失不只是“转写器听不清”，而是大量目标句在身份判断阶段被拒成空串。若把被接受目标字符占比记为 `rho`，其 accepted ASR CER 记为 `c`，则：

```text
CER_submit = 1 - rho * (1 - c)
```

由此可得：

| accepted ASR CER `c` | CER<=0.4 所需 `rho` | CER<=0.2 所需 `rho` |
|---:|---:|---:|
| 0.344 | 91.5% | 不可能 |
| 0.20 | 75.0% | 100.0% |
| 0.15 | 70.6% | 94.1% |
| 0.10 | 66.7% | 88.9% |

这把目标自然拆成两条战线：

1. **DACF-Gate（先攻 0.4）**：把 target presence/activity 做成真正的身份条件化判断，在 RR 基本不掉的前提下显著提高目标字符接受率。
2. **DACF-Latent（再攻 0.2）**：让反事实前端进入 ASR latent/encoder，并由 ASR loss 直接训练，把 accepted CER 压到约 0.15；仅靠放宽拒识不可能到 0.2。

## 2. 与旧路线的不可约区别

下列组件单独都不新：enrollment embedding、FiLM/cross-attention、target activity、零初始化 residual、TSE mask、ASR loss。项目也已经分别验证过 pBSRNN、same-env TSE、Qwen Sidecar、`max_sim+STNO`。

DACF 唯一值得继续的新增部分是下面三项必须同时成立：

1. **固定 mixture 的 query intervention**：A/B/C 查询共享同一个 mixture 哈希、环境、噪声和干扰内容，查询是唯一干预变量。
2. **身份与环境分工可审计**：speaker anchor 决定 presence/activity；environment anchor 只能调节声学适配，不能直接给 presence 投票。
3. **target-absent 完整指令负例**：C 不在 mixture 时，A/B 即使说完整家居指令也必须 blank，阻止模型退化成内容 gate。

缺少任意一项，DACF 都会退化成“Sidecar/TSE + 双分支外形”，不构成新机制。

## 3. 前端结构

```text
                         +--> 高能 speech frames --> speaker anchor --+
enrollment --> STFT -----|                                      identity query
                         +--> 低能 background frames --> env anchor ----+
                                                                     acoustic only
mixture --> STFT --> compact mixture encoder --> speaker-query frames --> env-adapted frames
                                              |                       |       |
                                              |                       |       +--> CTC / ASR latent bridge
                                              |                       +----------> full-range target mask
                                              +--> presence + target activity
```

设计防线：

- speaker/environment 使用不同 token 路径、不同 cross-attention 和不同监督；
- enrollment 先按相对帧能量做 speech/background 软划分，避免两个 anchor 只是同一特征复制；
- presence/activity 从 speaker-only 路径读取，environment branch 对这两个 head 无直接梯度；
- environment contrastive + speaker contrastive + 两空间 cross-covariance 约束只作为防泄漏先验，不能替代 2x2 因果测试；
- mask 初始严格为 identity，但参数范围允许走到 0；absent query 因而在表示能力上可以输出静音；
- 同 mixture、不同 query 的预测音频差分必须匹配监督目标差分，不能只靠三条独立 reconstruction loss。

## 4. 数据契约

每个反事实组至少有以下可执行事实：

| 字段/约束 | 要求 |
|---|---|
| `base_mixture_id` | A/B/C 三行相同 |
| `mixture_sha256` | A/B/C 三行相同，且运行前回读文件复核 |
| `query_role_id` | 仅表示组内 A/B/C 角色，不能作为全局 speaker label |
| `query_speaker_id` | 真实查询说话人身份，用于 speaker supervision |
| `environment_id` | 同环境组相同；train/val 环境隔离时必须可追踪 |
| enrollment | 1--2 秒；与 recognition source 不得为同一 utterance |
| absent C | 与 A/B 同环境、同质量范围，但 C 绝不在 mixture 中 |
| noise | 同 noise identity/type 可以；禁止复制 recognition 中完全相同的采样片段作为 enrollment shortcut |
| split | Dataset-A 禁止；训练/验证 speaker、utterance、content、environment 按实验目的隔离 |

## 5. 四层数据阶梯

### P0：AISHELL-1 小型机制集

- 用途：一批反传、固定-mixture 过拟合、query permutation 对照。
- 能回答：模型是否在计算图上听从 query。
- 不能回答：真实环境泛化、家居 hard negative、最终 CER。

### P1：REAL-PS4/AISHELL-4 环境 2x2 探针

本机有 6 个真实会议 session、每个 session 同一 4 位 speaker 的 109 条 enrollment 片段。完整 mixture/转写不在本机，但可以冻结模型后构造：

```text
正确 speaker / 同 session enrollment
正确 speaker / 跨 session enrollment
错误 speaker / 同 session enrollment
错误 speaker / 跨 session enrollment
```

用途：证伪环境 shortcut。它只有 4 位重复 speaker，因此不是 speaker-disjoint 泛化集，不能选阈值，也不能报告 CER。

### P2：真实家居指令小集

这是不可跳过的数据缺口。至少需要多位说话人在真实房间/设备上录制：

- target 在场说家居指令；
- distractor 在场说完整家居指令；
- query speaker 缺席；
- 同 speaker 跨房间、同房间跨 speaker。

没有这层，模型可能在 AISHELL read-speech 上很好，却继续被比赛中的“干扰人也说完整指令”击穿。

### P3：Dataset-A 冻结后一次性评测

Dataset-A 只能评测。不得用于训练、词表扩充、数据增强、阈值、选模或路线选择。P0--P2 的代码、权重、阈值和停止条件冻结后，才允许一次性同进程 paired evaluation。

## 6. 证伪顺序

### G0：数据不泄漏

必须全部通过：

- A/B/C mixture SHA 一致；
- source/enrollment utterance 不同；
- absent C 不在 mixture；
- query 行顺序随机化后结果不变；
- query label permutation 后性能显著恶化；
- train/val speaker 和 source 无交集。

### G1：四条 mixture 过拟合

只回答“可控性”，不回答泛化：

- qA/qB presence 高，qC presence 低；
- qA/qB 输出差分方向与 A/B clean target 差分一致；
- qC 输出 RMS 能趋近静音；
- enrollment 交换后输出随 query 交换，而非固定选择更响/更早的说话人。

### G2：未见 speaker 泛化

在非 A、speaker-disjoint 验证集同时看：

- char-weighted target presence recall；
- target-absent RR；
- hard-negative 完整指令 RR；
- 环境 2x2；
- clean/no-overlap 回退。

### G3：ASR 对齐

同一进程比较 raw mixture、zero-DACF、trained-DACF：

- paired cumulative CER；
- per-item CER delta 和 bootstrap 95% CI；
- presence/RR operating point；
- 输出音频与 residual norm；
- 可听样本；
- batch=1 RTF。

只改善 SI-SNR、mel、wave L1 或训练 loss，不算通过。

## 7. 继续与停止门槛

只有以下条件同时成立，才从小 POC 扩训：

- 固定-mixture query swap 对未见 speaker 有效；
- query permutation 对照明确失败，证明模型确实使用 enrollment；
- environment 2x2 不出现“错误 speaker/同环境优于正确 speaker/跨环境”；
- hard-negative operating point 达到目标 presence recall，同时 `RR >= baseline - 1pp`；
- 同进程 paired ASR `Delta CER <= -0.05` 且 bootstrap 95% CI 上界 `< 0`；
- clean/no-overlap CER 退化不超过 `0.005`；
- batch=1 前端 RTF 增量不超过约 `0.05`；
- 训练、阈值和选模全程未使用 Dataset-A。

任一实现出现以下情况，标为 `implementation-NO-GO` 并停止该实现：

- query swap 无效或打乱 query 后性能不变；
- presence recall 与 hard-negative RR 没有共同 operating point；
- environment branch 偏爱同环境错误 speaker；
- 只有代理损失变好，ASR CER 不变/变差；
- clean 样本 residual 大幅激活；
- 只在合成同环境成立，真实/跨环境消失。

上述停止只针对实现，不自动推出 DACF 整个方向封顶。

## 8. 计算路线

本机 RTX 4060 Laptop 8GB 足够做：

- 约几十万参数的 DACF 前端；
- 1--4 个固定 mixture 的过拟合与梯度审计；
- 冻结 Qwen 条件下的小 residual/adapter 验证（以实际接口和显存审计为准）；
- 非 A 小集的同进程 Qwen paired smoke。

L20 暂时不可租不构成当前阻塞。L20 只在 G0--G3 已通过、需要 batch=1 官方效率复核或扩量训练时再使用。

### Qwen 可微接点审计结论

当前 `code/qwen_asr_backend.py` 调用的公共 `transcribe()` 被 `torch.no_grad()` 包裹，并进入 `generate()`；它不接 labels、不返回 loss，也不暴露 audio hidden state。因此把 DACF 音频直接塞进当前提交封装训练属于 `implementation-NO-GO`。

底层并未封死：本地 Qwen3-ASR 的 `thinker.forward(...)` 接受 `labels` 并返回 CE loss，audio tower 也返回最终 `last_hidden_state`。项目已有 Sidecar 代码证明冻结 Qwen、保留 autograd graph、只训练注入模块的链路可运行。

接点优先级冻结为：

1. **audio encoder hidden state**：`conditional-GO`，DACF-Latent 的首选；复用 Sidecar 的层注入机制，但把普通 enrollment embedding 换成固定-mixture query-swap 学到的 speaker-query frames。
2. **Qwen-compatible mel**：`conditional-GO`，适合检查 `input_features.grad`；不是首选最终结构。
3. **waveform -> 当前 Qwen processor**：`implementation-NO-GO`。Whisper feature extractor 会转 NumPy，waveform 到 ASR loss 的梯度在这里断开；除非以后用 torch 精确重写 128-bin log-mel 和 padding。

硬件裁决：

- 4060 8GB 全参 Qwen：`implementation-NO-GO`；
- 现有纯 ASR LoRA：容量上 `conditional-GO`，但没有 enrollment conditioning，不是 DACF；
- 冻结 Qwen、batch=1、只训练 DACF/latent residual/presence head：一批梯度 smoke `conditional-GO`；
- Qwen 参数必须 `requires_grad=False`，但 forward 不能放在 `torch.no_grad()` 中，否则 ASR loss 无法回到 DACF。

DACF-Latent 的第一条通过标准不是 loss 数值下降，而是同时证明：Qwen loss 有限、DACF 参数梯度有限且非零、冻结 Qwen 参数无梯度、zero-DACF 与 baseline 输出一致。

### 真实 Qwen batch=1 结果

已在本地 `Qwen3-ASR-1.7B` 和 RTX 4060 Laptop 8GB 上完成严格 smoke：

- baseline loss 与 zero-gate loss 均为 `6.7147307396`，logits 最大绝对差和 loss 差均为 `0`；
- zero gate 的纯 ASR backward：gate 梯度 `0.5859375`，DACF 非零梯度张量数 `0`。这是乘法门控在严格 identity 初始化下的预期数学结果，不能伪装成“首步 ASR 已进入 DACF”；
- gate=`0.01` 后只反传纯 ASR loss：7 个 bridge 参数张量、36 个 DACF 参数张量得到有限非零梯度，冻结 Qwen 梯度泄漏为 `0`；
- 真实 audio layer 输出为 `[127,1024]`、`bfloat16`、`[T,H]`，每次 forward 调用 audio tower 1 次；
- 三次 forward/backward 核心 smoke 用时 `1.680 s`，峰值 allocated/reserved 显存 `4891.58/4926 MiB`。该时间不是 batch=1 RTF，不能拿去报效率分。

这只证明 4060 上的接口、梯度和显存成立，不证明训练后 CER 会改善。

## 9. G2-mini 首次执行与失败归因

在看结果前固定门槛：阈值恒为 `0.5`，val AUC `>=0.80`、present recall `>=0.75`、absent RR `>=0.75`、query permutation response `>=0.20`。随后构造 24 个 train mixture / 8 个 val mixture，共 96 行；train 72 位 query speaker、val 24 位，speaker/source overlap 均为 0，全部 mixture SHA 回读一致，Dataset-A 使用数为 0。

240 个固定 update 后结果：

| 指标 | train | speaker-disjoint val |
|---|---:|---:|
| present-vs-absent AUC | 0.5443 | 0.5234 |
| present recall @0.5 | 0.2917 | 0.3125 |
| absent RR @0.5 | 0.7917 | 0.8750 |
| present probability mean | 0.4915 | 0.4920 |
| absent probability mean | 0.4882 | 0.4929 |
| query permutation response | 0.00337 | -0.00093 |
| presence loss | 0.6904 | 0.6946 |

这里的 A/C、B/C permutation response 是同一 presence margin 的成对干预写法，用来确认只换 query 后输出随之变化，不把它冒充成第二个独立统计证据。

训练总 loss `2.5497 -> 1.8649` 看似下降，但分解后可见 presence/activity 仍接近随机 BCE；主要收益来自 reconstruction。val absent 输出 RMS 从 `0.03942` 降到 `0.000516`，模型实际上走向了“整体低能量/近静音”解，而不是学会 enrollment 身份匹配。单组 G1 能记住 A/C，到了未见 speaker 连训练集 AUC 都接近随机，说明 24 组规模下让小 STFT 网络同时从零发明 speaker encoder 与 target matcher 是错误任务分配。

精确裁决：**随机初始化 speaker encoder 的 DACF-v1 = `implementation-NO-GO`**。它不允许扩量、续训或用 val 调学习率；但不推出固定-mixture 反事实监督、预训练 speaker manifold 或 Qwen latent 联合训练是 `direction-NO-GO`。

### DACF-v2 / v2b 决策

DACF-v2 已冻结本机 CAM++ 并完成两级无训练审计：

1. enrollment 两个独立 view 的 512d 最终 embedding；
2. 同一 mixture 只提取一次 whole + 1.5 s / 0.5 s hop embedding，A/B/C 三行严格复用；
3. 不安装 `onnx`，用 protobuf 保留未知字段的方式复制原图，把统计池化前节点 `onnx::ReduceMean_4602` 声明为额外输出，得到 `[B,512,T]`；原始模型未修改；
4. 用 sherpa stream 的原生 fbank 直接送修改图，最终 embedding 与既有 D9 产物余弦为 `1.000000`，排除了前端不等价；
5. clean enrollment 主/副 view 的同 speaker vs different speaker AUC 在 train/val 均约 `0.971`，但 mixture whole/window、pre-pool raw cosine 和 train-only diagonal whitening 全部接近随机。

精确裁决：**“分别编码后再做 whole/window/pre-pool cosine”均为 `implementation-NO-GO`**。失败不是 CAM++ 不会认人，而是混合侧在无条件编码后没有形成可由简单后验相似度读取的双说话人身份。

DACF-v2b 只学习本项目真正新增的 cross-query：

```text
frozen CAM++ enrollment final embedding -- Wq --+
                                                  low-rank match -> activity/presence
frozen CAM++ mixture pre-pool tokens ----- Wm --+                 -> query-aware tokens
```

- `Wq/Wm` 为 bias-free 低秩投影，matcher 参数必须 `<100k`；
- 模型输入只有 mixture tokens 与 enrollment embedding，`query_role_id` 只用于审计和组内 loss，绝不能入模；
- presence/activity 先通过固定 24/8 speaker-disjoint G2；environment anchor 仍不得给 presence 投票；
- 若低秩 matcher 也失败，该具体 CAM++ cross-space 实现停止，不用 val 调层、温度、窗口或阈值；方向随后转到 waveform/log-mel 编码早期的 target-conditioned mask/ASR，而不是继续修 cosine。

## 11. 外部工作仅作为边界，不作为照抄路线

- TS-ASR-AD：证明联合 ASR+speaker activity 的技术边界，但其 enrollment、数据和任务条件不能替代本项目的固定-mixture A/B/C 因果监督：<https://www.isca-archive.org/interspeech_2025/maeda25_interspeech.html>
- Robust pVAD：提示 hard sample、domain mismatch 与 false accept 是必须正面解决的问题：<https://www.isca-archive.org/interspeech_2025/lin25_interspeech.html>
- Self-speaker adaptation：说明 speaker-specific kernel 可在 ASR pre-encode/encoder 层注入，但没有 enrollment query，也没有替 DACF 解决 absent-command 反事实：<https://www.isca-archive.org/interspeech_2025/wang25y_interspeech.html>
- Lightweight target-speaker FiLM：证明轻量条件化可行，但 FiLM 本身不是本项目的原创点：<https://arxiv.org/abs/2506.20288>
- Direct T-F enrollment context 与 USEF-TSE：都已证明 enrollment 的时频上下文可直接和 mixture 交互，因此“早期时频交互/不用单个 speaker embedding”也不能单独当原创贡献：<https://arxiv.org/abs/2402.17146>、<https://arxiv.org/abs/2409.02615>

因此 DACF-v3 可检验的新增点不是 Conv、FiLM、cross-attention、mask 或 joint VAD/ASR 这些已有积木，而是它们在本题下的**因果训练与拒识契约**：同一 byte-identical mixture 上只干预 enrollment 的 A/B/C 三查询、显式 absent-C blank、environment-to-presence firewall、双 enrollment view、未见 speaker gate，以及在 frozen Qwen 上保持 baseline 精确不变的 zero-gated latent retrofit。最终能否构成有效贡献仍由这些反事实门和 paired CER 决定。

## 13. DACF-v3 ECST 预注册方向（早期条件时频传输）

### 13.1 主判断

v2b 的失败不是“参数太少”这么简单：scale-only 训练集 AUC 也只有约 `0.72`，final 的 query-response 置信区间整体为负。继续对 frozen CAM++ mixture token 堆 MLP、attention 或扩大数据，只是在同一个错误信息瓶颈后加容量。FiLM 早注入、enrollment 时频交互和 joint activity+ASR 均有公开先例，ECST 名称不改变这一事实；本轮只检验上述 DACF 反事实契约能否让一个轻量、可训练的 mixture encoder 真正学会 query identity。

DACF-v3 的唯一首选改为 **ECST（Early Conditional Spectro-Temporal Transport）**：冻结 CAM++ 只提供稳定 enrollment identity anchor；mixture 侧不再先无条件压成 speaker token，而是在第一层可训练时频卷积后就注入 query，形成 query-conditioned temporal representation，再输出 activity/presence 与未来的 Qwen latent residual。

```text
Qwen-exact 128-bin log-mel X ------------------> trainable TF stem ---> temporal blocks ---> Hq
                                                         ^                    ^
frozen CAM++ enrollment e[512] -> q[64] -> first FiLM/gate+--------------------+

Hq -> identity affinity + activity head -> activity / presence
Hq * activity -> Z[128]                  -> zero-gated Qwen early-latent residual
```

关键约束：

- log-mel 规格绑定本机 Qwen processor：`feature_size=128`、`n_fft=400`、`hop_length=160`、`dither=0`；模型只接 processor 产出的 feature，不另写一个近似 mel 前端；
- query 在第一层 mixture 卷积后立即进入，并继续调制 dilation=`1/2/4/8` 的轻量 depthwise temporal blocks；mixture encoder 可训练；
- 主产物是 `query_conditioned_frames [B,T,128]`，activity 是身份条件化辅助监督和 residual gate；mel mask 只允许作为诊断 ablation，不能把 mel/L1 改善冒充 CER；
- 第一版不引入 environment branch，先堵住“同录音设备/同房间”捷径；`query_role_id`、文件顺序、路径和 A/B/C 位置永远不能入模；
- 前端可训练参数 `<2M`，Qwen 参数冻结；Qwen bridge 保持 zero gate，baseline 必须精确不变，但 query projection 不得全零到切断身份梯度。

当前纯模型骨架默认只有 `428,162` 个可训练参数，shape/短序列/top25 presence/query 响应/双路梯度/输入防护测试已通过。真实特征 G1 固定用旧 scale 数据中的 `train_mix_0000`，60 step、lr=`0.003`、seed=`20260806`：loss `1.4131 -> 0.3523`，主/副 enrollment view 的 absent presence=`0.00276/0.00261`，两条 present=`0.9797--0.9951`；交换 absent 与一条 present enrollment 后 presence 同步互换，最大误差 `1.16e-9`。该结果只把 v3 计算图标为 G1 `conditional-GO`，不能用来选择超参，也不能外推未见 speaker、CER、RR 或 RTF。

### 13.2 为什么 0.4 与 0.2 是两种难度

令目标字符被正确保留的比例为 `rho`，被接受目标的 ASR CER 为 `c`：

```text
CER_submit = 1 - rho * (1 - c)
```

若 `c=0.344`，要到 CER `0.4` 需要 `rho>=0.915`；即使 `rho=1`，也到不了 `0.2`。所以 presence/activity 有机会把系统推向 `0.4` 档，但 `0.2` 必须同时让 query-conditioned latent 真正降低 accepted ASR CER，不能靠拒识阈值或 activity mask 外推。

### 13.3 官方 split 数据协议

本机 AISHELL-1 official split 的 speaker 数已现场核对为 train/dev/test=`340/40/20`。每个 byte-identical 反事实组严格使用 A/B/C 三位不同 speaker，且 split 内 speaker 不复用时，理论容量只有 `113/13/6` 组；因此审查稿里“dev/test 各 16 组”不可执行，禁止通过重复 speaker 假装独立样本。

v3 首轮固定为：

| 用途 | official split | 组数 | query 行 | 角色 |
|---|---:|---:|---:|---|
| train | AISHELL train | 96 | 288 | 只优化参数 |
| dev | AISHELL dev | 12 | 36 | 先过机制门；不调 presence threshold |
| final | AISHELL test | 6 | 18 | 代码、seed、步数、checkpoint、threshold 冻结后只打开一次 |

train/dev/final 的 speaker、source utterance path/SHA、mixture path/SHA、enrollment source/SHA 必须全为 0 overlap。A/B/C 三行共享同一 mixture SHA；C enrollment speaker 绝不在 mixture；两套 enrollment view 来自不同片段并独立增强。AISHELL read speech 的 `hard_negative_verified_count=0` 必须显式保留，因此即使 official final 通过也最多是 `conditional-GO`。

### 13.4 反捷径与阶段门

先只跑 dev；两个 enrollment view 必须同时满足：

- presence AUC `>=0.85`；
- activity AUC `>=0.80`；
- present recall `>=0.80`；
- absent RR `>=0.95`（dev 的 12 个 absent 至多允许 0 个漏过，避免小样本四舍五入）；
- mean query-response `>=0.20`，group-bootstrap 95% CI 下界 `>0.05`；
- enrollment 跨组 permutation 后 AUC 至少下降 `0.15`；
- 当前 AISHELL 机制协议不保证构造 same-text/different-speaker 对，因此该项不能在本阶段伪造为可计算硬门；它被前移为 **接 Qwen 前的专门真实家居 hard-negative gate**，届时必须构造同指令/不同说话人样本并要求 AUC `>=0.75`；
- 按 target 能量、先后顺序、overlap、source A/B 角色分桶后，不得出现由单一捷径支配的翻转；
- clean/no-overlap 的 latent residual 接近 0，避免无条件改写本来正确的语音。

dev 任一失败即把该实现标成 `implementation-NO-GO`，不打开 official test，不换 seed 扫参数。dev 全过后冻结产物，只在 official test 运行一次同样 gate；test 只有 6 个独立组，必须同时报告原始计数与 group-bootstrap CI，不能只报行级 AUC。

final 通过后仍不能直接接提交线。先补非 Dataset-A 的真实家居 hard negative（干扰人说完整指令）并要求 RR 相对当前基线下降不超过 `1pp`；随后才允许冻结 checkpoint 接 Qwen，同进程 paired gate 固定为：累计池 `Delta CER<=-0.05`、bootstrap 95% CI 上界 `<0`、clean/no-overlap CER 退化 `<=0.005`、batch1 前端 RTF 增量 `<0.05`，并保留逐条可听证据。只有全部通过才是 `integrate-GO`。

## 14. DACF-v3 正式裁决与 DACF-v4 修复路线

### 14.1 正式 v3 结果

正式协议为 `dacf-v3-mechanism-protocol-v0.2`：AISHELL official train/dev/test 对应 `96/12/6` 个反事实组，train/dev/final 的 speaker、源音频路径与 SHA、mixture 路径与 SHA 全部零重叠；Dataset-A 使用数为 0。缓存只包含 train/dev，official final 在特征、训练和裁决链中均未打开。训练合同在运行前独立固化：seed=`2026080606`、AdamW、lr=`3e-4`、weight decay=`1e-4`、FP32、20 epoch、每个 epoch 96 个完整 A/B/C 组、共 1,920 update、无 scheduler、无 early stop、无超参扫描、threshold=`0.5`、bootstrap=`2000`。最终 checkpoint 在 dev 前冻结，dev 只观察一次，观察前后 SHA256 均为 `3d03e238...8f41`。

两个 enrollment view 的正式 dev 结果如下：

| 指标 | view1 | view2 | 固定门 |
|---|---:|---:|---:|
| presence AUC | 0.4618 | 0.4167 | >=0.85 |
| activity AUC（仅 present 行） | 0.6102 | 0.6085 | >=0.80 |
| present recall | 0.5833 | 0.5833 | >=0.80 |
| absent RR | 0.4167 | 0.3333 | >=0.95 |
| query-response mean | -0.0317 | -0.0645 | >=0.20 |
| query-response group-bootstrap 95% CI lower | -0.1640 | -0.2273 | >0.05 |
| query permutation AUC drop | -0.0278 | -0.1285 | >=0.15 |

所有机制门均以大幅度失败，因此精确裁决是：**冻结 CAM++ enrollment + 早期 FiLM ECST + v0.2 一人一角色协议 = `implementation-NO-GO`**。loss 从 `1.4807` 降到 `1.0995` 不能推翻门控结果。该轮没有打开 official final，没有连接 Qwen，也没有测 CER、official neg RR、clean degradation 或 RTF；same-text/different-speaker 仍按预注册留给真实家居 hard-negative 套件，不能把本轮结果外推成整个前端方向封顶。

### 14.2 训练集反查揭示的真正根因

dev 失败后只用已冻结 checkpoint 做了 train-only 诊断，不改模型、不选 checkpoint、不接触 final：两个 view 的 train presence AUC=`0.935/0.951`、present recall=`0.953/0.964`、absent RR=`0.708/0.729`、query-response=`0.444/0.453`；但 activity AUC 仍只有约 `0.635`，query permutation AUC drop 也仅约 `0.064`。这不是容量不足或“再训几轮”能解释的形态：模型很会在训练 speaker 上报 present/absent，却没有学会 query 与当前 mixture 的可迁移身份关系。

根因在 v0.2 协议：为了让 96 组 speaker 完全独立，每位 train speaker 只在一个组、一个角色中出现一次。于是 speaker embedding 本身与标签高度绑定，网络可从 query 独立记住“某人是 A/B/C”，无须判断这个人是否真的出现在 mixture。FiLM 允许 query 直接改变 hidden state，又给这条捷径留下了足够容量。原先的跨组 query permutation 虽能检测一部分问题，却发生在未见 speaker dev 上，不能阻止训练阶段形成 speaker→role 记忆。

### 14.3 DACF-v4：角色轮换 + 关系瓶颈

v4 不做 v3 参数微调，而是同时改训练识别性和模型可辨识性：

1. **角色轮换协议**：train/dev/final 继续 official speaker-disjoint，但 train 内主动复用 speaker。每位 speaker 必须在不同 mixture、不同源句、不同 SNR/overlap 条件中多次出现，并平衡承担 present 与 absent；同一个 speaker embedding 不再能预测标签。音频文件不能复用，所有源路径/SHA 仍逐条审计。
2. **显式关系瓶颈**：mixture encoder 产生逐帧归一化 identity key `k_t`，enrollment 产生归一化 query `q`。activity/presence 的主 logit 必须来自 `tau*cos(k_t,q)`，可加只读取 `k_t*q` 与 `|k_t-q|` 的小型 relation MLP；禁止使用 q-only、role id、路径、顺序或 environment 特征预测标签。
3. **跨环境身份监督**：一个 batch 放入多个 mixture，其他 enrollment 自动成为 foreign negatives；同 speaker 的不同 utterance/view 是 positive。用 cross-batch contrastive/BCE 明确训练“这个 query 是否属于这条 mixture”，而非只训练 A/B/C 三个位置。
4. **更强反捷径门**：除未见 speaker 的双 view 门外，新增 query-only 与 mixture-only ablation；保持 q、打乱 mixture 后 AUC 必须崩到随机，保持 mixture、打乱 q 后 activity/presence 必须同步变化。跨组 permutation 必须通过约束匹配构造，不能再假设简单 `+1` 一定是 foreign query。

v4 的第一阶段仍只验证 identity/presence/activity，不消耗 Qwen；若关系门不过，继续标记该实现 `implementation-NO-GO`。只有未见 speaker dev、真实家居同文本 hard negative 和双 enrollment view 都过门，才进入 Qwen latent paired CER。这个路线针对的是 v3 已实证的捷径，不把换名字或增加参数冒充突破。

## 15. DACF-v4a all-pairs 结果与 v4b 角色轮换决策

### 15.1 v4a：同一 query 在同一 update 中同时取得正负标签

v4a 先复用 provenance-locked 的 v3 train/dev 特征缓存，不重新生成音频。每个 8-mixture batch 只取各组的 present-A/present-B enrollment，形成 16-query bank；标签不继承 query 的源组角色，而按 `query_speaker_id in destination_mixture_speakers` 重新计算。于是每个 query 在同一次 update 中恰好有 1 个 positive mixture 和 7 个 foreign mixtures，原 C-only speaker 不参与优化。30 epoch 后，96 个 train group 的有向 foreign-pair 覆盖率为 `89.89%`。模型把 mixture 独立编码成 normalized frame key，把 query 编成 normalized embedding，activity/presence 只读 key-query product/cosine；query 不再 FiLM mixture hidden state。

训练合同在运行前固定：seed=`2026080617`、8 groups/batch、30 epoch、360 optimizer update、AdamW lr=`3e-4`、weight decay=`1e-4`、FP32、无 scheduler/early stop/扫参、threshold=`0.5`、2000 次 bootstrap、dev 只观察一次、final deferred。预注册 SHA256=`dfb0d6ac...4f273`。

正式结果：

| split/view | presence AUC | activity AUC | recall | foreign RR | top-2 exact | query->mixture top1 | query-response |
|---|---:|---:|---:|---:|---:|---:|---:|
| train view1/view2 | 0.763/0.764 | 0.625/0.622 | 0.870/0.828 | 0.509/0.510 | 0.021/0.010 | 0.052/0.073 | -0.066/-0.061 |
| dev view1/view2 | 0.682/0.664 | 0.629/0.626 | 0.792/0.792 | 0.443/0.462 | 0/0 | 0.208/0.208 | -0.033/-0.036 |

相较 v3 的 dev presence AUC `0.462/0.417`，all-pairs 明显学到了一部分可迁移关系；mixture permutation AUC drop 也到 `0.194/0.172`。但 activity、RR、retrieval 与 query-response 仍大幅失败，最难 foreign 的分数平均高于真实 target。精确裁决：**learnable query projection + all-pairs relation v4a=`implementation-NO-GO`**；没有打开 final、连接 Qwen或测 CER/RR/RTF。

### 15.2 train-only 根因：query projection 压塌了健康的 CAM++ 几何

冻结 v4a checkpoint 后只在 train 做几何诊断：原始 CAM++ 双 enrollment view 的同人/异人余弦均值为 `0.916/0.436`，cross-view identity AUC=`0.9728`；经可学习 512->64 query projection 后，同人/异人变成 `0.988/0.921`，AUC 仍有 `0.9567`，但绝对 margin 被严重压扁。纯 cosine presence AUC=`0.763/0.764`，与完整 relation 输出基本相同，说明 relation MLP 没有恢复身份间距。

据此预注册一个严格单变量结构 A/B：删除 query projection 和 relation MLP，query 只做 raw CAM++ 512d L2 normalization；mixture encoder 独自学习 512d frame key，pair logit 仅为 scaled cosine + 一个全局校准 bias。其余 cache、pairing、loss、seed、步数和 gate 完全不变。模型 386,098 参数，预注册 SHA256=`e1318a95...7e03f`。

anchor-preserving 正式结果：

| split/view | presence AUC | activity AUC | recall | foreign RR | top-2 exact | query->mixture top1 | query-response |
|---|---:|---:|---:|---:|---:|---:|---:|
| train view1/view2 | 0.784/0.785 | 0.647/0.647 | 0.938/0.932 | 0.441/0.441 | 0.010/0.010 | 0.052/0.042 | -0.049/-0.048 |
| dev view1/view2 | 0.659/0.650 | 0.629/0.631 | 0.917/0.875 | 0.326/0.341 | 0.167/0.167 | 0.208/0.167 | -0.053/-0.045 |

保住 anchor 令 train 指标和 dev top-2 有局部改善，但未见 speaker AUC 没改善，foreign RR 更差，query-response 仍为负。精确裁决：**raw CAM++ anchor + 单正环境 all-pairs=`implementation-NO-GO`**。这排除了“只要冻结 query 空间即可”的轻量修复，但没有排除关系前端方向。

### 15.3 为什么下一步必须是 v4b，而不是再调网络

v4a 的每个 A/B speaker 虽在不同 destination mixture 上同时得到 present/absent 标签，但它只在一个 mixture 中真正以语音出现，正例仍绑定到单条 utterance/单个 environment。mixture encoder 可以学到局部 utterance/acoustic 相似性，却没有被要求把同一个 speaker 在多条源句、多种 overlap/SNR 和 A/B 角色下映射到同一身份。因此 anchor 版 train presence AUC 也只有约 `0.79`，不是单纯 dev 过拟合。

v4b 固定数据协议改为：

- train 选 48 位 AISHELL-train speaker，6 round x 16 group=`96` 组；每 round 每位 speaker 只出现一次，6 round 后每人严格 `2A+2B+2C`，即 4 次 present、2 次 absent；
- dev 选 12 位 official-dev 未见 speaker，按同一轮换构造 24 组；official test/final 继续不读取；
- 每次 present 使用 recognition、enrollment view1、enrollment view2 三个不同源 WAV；每次 absent 使用两个不同 enrollment 源 WAV，所以每位 speaker 固定消耗 16 个不同源 WAV。本机 train/dev 每 speaker 最少有 312/335 条，容量不是限制；
- 新增全局 path/SHA 使用账本，任一源 WAV 在整个 split 中使用次数必须为 1；view1/view2 必须绑定不同源 WAV；
- 每 round 分别打乱 A/B/C 池后配组，同时约束 partner pair 不重复；A/B 混音与增强必须交换对称，不能沿用旧 builder 中只作用于 A 的变速路径；
- all-pairs foreign label 继续按 destination mixture membership 重算；speaker 重用后禁止把“来自别组”直接当 negative；
- dev 除原机制门外，A/B role recall 各自 `>=0.75`，collapsed-query/collapsed-mixture AUC `<=0.55`，所有 source path/SHA 全局唯一。

v4b 是针对两个正式实验共同暴露的“单正环境不可辨识性”做数据与因果合同修复，不是延长训练或换 seed。只有 v4b 未见 speaker dev 通过，才允许生成 final feature；在此之前提交线和 CER 结论均不变。
