## 一、背景与目标

### 为什么要做
- 三轮合成训练全部 NO-GO，根因相同 = **合成数据域不匹配墙**：
  - Qwen LoRA POC（Aishell 新闻朗读 + 程序噪声）：A 集 holdout CER **0.344 → 0.491（Δ+0.147 翻车）**
  - Phase-3 Sidecar（AISHELL-1 + MUSAN）：CER 0.343 → 0.376（Δ+0.034 显著回退）
  - TSE pBSRNN Phase-2：Δ−0.02 未过门槛
- 域不匹配的三条代码级根因（本次调研坐实）：
  1. **文本域**：AISHELL-1 是新闻朗读，≠ 家居指令（空调/灯/温度）。
  2. **重叠相位**：`simulate_pipeline.mix_overlap` 是纯线性叠加（`out[:overlap_len] += interferer`），无 RIR、无到达时延、无相位差——`build_aishell_manifest.py` 还在直接读新闻 transcript。
  3. **小声/快语速**：程序 `make_quiet`/`make_fast` ≠ 真实小声。
- **声纹多样性缺口**：本机唯一 TTS（MiMo 云端）只有 2 音色，覆盖不了题目 20+ 唤醒人声。

### 目标
造一份**域匹配的中文家居指令 + 真实化重叠相位**数据集，喂给 Phase-3 Sidecar（ASR-loss 反传，TSE 唯一未试路径），目标 A 集 holdout **ΔCER ≤ −0.05**（GO 门槛）。

### 非目标
- 不替换主线提交线（qwen 含拒 CER 0.6201）。
- 不碰 Dataset-A 训练（泄漏=作废，红线）。
- 不在本阶段做 Whisper-Sidecar（护城河冲刺备选，需 8×V100，另议）。

## 二、核心策略：破域不匹配墙

| 根因 | 对策 | 落点 |
|---|---|---|
| 文本域（新闻≠家居） | **CosyVoice 2 合成家居指令**（用扩充的 HOME_CMD_TEMPLATES） | 阶段 1-2 |
| 声纹多样性（仅 2 音色） | **3s 零样本克隆**：用 AISHELL-1 的 340 真实说话人各取 3s 当 prompt | 阶段 2 |
| 重叠相位（线性叠加） | **MIT IR Survey 271 真实 RIR 卷积**，两人不同 RIR | 阶段 3 |
| 小声/快语速（程序） | 保留 `make_quiet`/`make_fast`，但作用在 TTS 干净音频上（更真实） | 已有 |

**POC 验证逻辑**：新数据（TTS+RIR）→ 重跑 LoRA POC → 对照 0.491。若显著下降 = 域匹配改善坐实，再扩规模训 Phase-3。**先证伪再投入**，避免重蹈"loss 收敛但 hold-out 退化"覆辙。

| 项 | 决策 | 理由 |
|---|---|---|
| TTS | **CosyVoice 2**（Apache-2.0） | License 干净（比赛零风险）+ 3s 克隆扩 20+ 声纹 + 中文业界标杆 |

## 四、阶段详解

### 阶段 0：部署 CosyVoice 2（code/.venv_tts）
**目标**：本地可批量合成 20+ 声纹中文家居指令。

步骤（以官方 README 为准，大致）：
1. `uv venv code/.venv_tts`（独立 venv，遵循"新依赖一律独立 venv"教训，不污染主 .venv / .venv_qwen）
2. clone `github.com/FunAudioLLM/CosyVoice`，按其 requirements 装（含 torch，约 6-8GB 显存，本机 4060 8GB 充裕）
3. 下模型 `FunAudioLLM/CosyVoice2-0.5B`（~2GB，HF，走代理或镜像）
4. 冒烟：用 AISHELL-1 某说话人 3s wav 当 prompt，合成一句"空调调到 26 度"，人耳验
5. 封装 `code/tts_home_cmd_gen.py`：输入 `{text, prompt_wav, spk_id}` → 输出干净单声 wav

**产物**：`code/.venv_tts/`、`code/tts_home_cmd_gen.py`、冒烟样本 wav
**风险**：CosyVoice 首次部署依赖较多（torch 版本/ CUDA 兼容），预留半天调试；若卡死切 GPT-SoVITS。

### 阶段 1：家居指令语料构造
**目标**：扩充 HOME_CMD_TEMPLATES 到 ~1-5 万条指令文本（不碰 A 集标注）。

现状：`code/data_aug_recipe.py:77-93` 的 `HOME_CMD_TEMPLATES` 仅 9 类 31 模板 + ~10 占位 = 数百变体（远小于外部 NLP-CSmHomComC 的 15264 句）。

步骤：
1. 基于现有 9 类（空调/灯/洗衣机/温度/风速/窗帘/音乐/模式/通用）扩充模板池
2. 用 LLM（Qwen/本地）按题目指令分布批量生成变体（20 唤醒词 × 动作 × 参数 × 说法），人工抽检合规
3. 同步造**干扰闲话文本池**（新闻/财经/闲聊，非家居指令）作 interferer
4. 导出 `code/home_cmd_corpus.jsonl`（字段：text, category, is_target）

**红线**：不从 Dataset-A 的 pos.jsonl/标注提炼文本（只用 HOME_CMD_TEMPLATES 词表骨架 + LLM 扩写）。

### 阶段 2：TTS 批量合成干净音频（20+ 声纹）
**目标**：合成 target/interferer 干净单人 wav 池。

步骤：
1. 从 AISHELL-1 train 的 340 说话人各取 1 条 3s wav 作 CosyVoice prompt（声纹克隆源）——天然 20+ 声纹
2. 对每个 (说话人, 家居指令文本) 合成干净 target wav → `tts_pool/target/{spk_id}_{cmd_id}.wav`
3. 对干扰闲话文本用不同说话人合成 interferer wav → `tts_pool/interferer/`
4. 装配 manifest：`{wav, ref: transcript, spk: spk_id}`

**产物**：`code/_tts_pool/{target,interferer}/*.wav` + manifest.jsonl（gitignore，保文本+种子可重生）
**规模**：POC 用 20 声纹 × 50 指令 = 1000 target；扩到 1000 声纹 × 30 = 30k。

### 阶段 3：RIR 卷积改造（核心）
**目标**：给 `synthesize_tse_triple` 加真实房间混响，补重叠相位。

数据：下载 MIT IR Survey 271 个真实 RIR（royalty-free）→ `E:/midea_datasets/rir_mit/`

改造点（`code/tse_data_aug.py`）：
- 新增 `code/rir_augment.py`：`load_rir_pool(dir)` + `apply_rir(wav, rir, rng)`（用 `torchaudio.functional.fftconvolve`，裁到原长）
- 在 `synthesize_tse_triple` 注入（**精确位置**）：
  - **target**：step 1（第 294 行 `t = target_wav...`）`make_fast` 之后，对 `t` 卷积 `rir_target`
  - **interferer**：step 4（第 313 行 `mix_with_random_timing`）调用前，对 `interferer_wav` 卷积 `rir_interferer`
  - 两人随机抽**不同** RIR（模拟不同位置/距离）
- **⚠️ SI-SDR 对齐红线**：target 的 RIR 必须同时作用到 `clean_target`（因为 `clean_target` 来自 `nominal_clean_target`，而后者来自 `t`）——即先卷积再进 `mix_with_random_timing`，保证 `recognition` 里 target 贡献与 `clean_target` 完全对齐。否则重蹈 07-29"独立裁剪致 SI-SNR 错位"bug。
- enrollment 是否卷积：**不卷积**（enrollment 是另一 utterance 的近场参考，保持干净更贴题目 enrollment 采集方式；若验证需再议）

**产物**：`code/rir_augment.py`、`tse_data_aug.py` 改动（加 `rir_pool` 参数 + 两处卷积）
**验证**：单条合成后听 recognition（应有真实混响感）+ 检查 `clean_target` 与 recognition 中 target 段 RMS 一致。

### 阶段 4：合成 TSE 三件套数据集
**目标**：用改造后的骨架合成 speaker-disjoint triples。

复用 `tse_data_aug.build_tse_pairs`（签名已确认，第 374 行），输入：
- `target_items` = 阶段 2 的 TTS target manifest
- `interferer_items` = 阶段 2 的 interferer manifest
- `noise_items` = MUSAN（env）+ 程序 white/pink/babble
- `augmentation_profile="balanced"`（按失败分布加权：overlap 偏中高、SNR 偏低、babble 多）

参数分布（对齐题目 + 失败组，来自 `tse_train_plan.md:178-188`）：
- overlap [0,0.25,0.5,0.75,1.0] → [0.10,0.10,0.25,0.30,0.25]
- SNR [-5,-3,0,3,5] → [0.20,0.25,0.30,0.15,0.10]
- noise [white,pink,babble] → [0.25,0.25,0.50]
- target_gain -8~-3dB(0.5)/0(0.5) + speed 1.1~1.4(0.3)/1.0(0.7)
- enroll 1.5~2.5s + 30% 污染

输出：`{enrollment,recognition,clean_target}/*.wav + manifest.jsonl`（含 measured_sir/snr）

**speaker-disjoint**：train/val 说话人严格不交叉（复用现有 split 规范）。
**产物**：`code/_tse_home_manifests_{train,val}/`（gitignore，~3GB 可重生）

### 阶段 5：预计算 enrollment_embedding + target_activity
**目标**：生成 Phase-3 训练 manifest（`tse_qwen_sidecar_train.py` 硬要求字段）。

`tse_qwen_sidecar_train.py` 的 `_validate_rows` 要求每行有：
`id, recognition_audio, target_src, target_spk, ref, enrollment_embedding, target_activity`

步骤：复用 `code/tse_campp_embeddings.py`（07-29 已存在）：
1. 对每条 triple 的 enrollment wav 算 CAM++ embedding → `enrollment_embedding`
2. 对 clean_target 算语音活动 mask → `target_activity`
3. 合并成训练 manifest，**必须含 `/wav/train/` 路径 token**（否则被 BANNED_PATH_TOKENS 校验拒）+ Dataset-A 泄漏校验

**产物**：`code/_tse_phase3_manifests_home_{train,val}/manifest_campp.jsonl`

### 阶段 6：POC 验证（重跑 LoRA POC 对照 0.491）
**目标**：用 ~1k 新数据验证域匹配是否真改善（最经济证伪）。

步骤：复用 LoRA POC 链路（`code/runs/_qwen_lora_poc/` 已有），把训练数据换成阶段 4 的 1k TTS+RIR triples，A 集 holdout 评估。
- **对照基线**：旧 LoRA POC CER 0.491（Aishell 新闻朗读+程序噪声）
- **GO 判据**：新数据 LoRA POC CER 显著低于 0.491（如 ≤0.45，且 bootstrap CI 不跨旧值）= 域匹配改善坐实
- **NO-GO**：新数据仍 ≥0.49 → 域匹配假设证伪，停止扩规模，回到分场景路由/L20 验证主线

**这一步是整个方向的生死门**——GO 才进阶段 7。

### 阶段 7：Phase-3 训练（tse_qwen_sidecar_train，L20）
**目标**：GO 后扩 30k 数据，租 L20 跑 Phase-3 ASR-loss 反传。

训练配置（`tse_train_plan.md:280-299`）：
- L20 48GB，batch=8，seg=48k → ~15GB，~0.2-0.3s/step
- 10 万 step ≈ 6-8h，~64 元/round
- 冻结 Qwen3-ASR encoder 前 1/3 层 + rank-64 Sidecar + target activity head（新增参数 <5%）
- ASR loss 直接反传（不优化 SI-SNR/mel 代理）

入口：`code/tse_qwen_sidecar_train.py --train-manifest ... --val-manifest ...`（无 Dataset-A 选项，防泄漏）
预算：3-5 round 调参，总 <500 元。

### 阶段 8：A 集 holdout 验证 + GO/NO-GO
**目标**：锁定 checkpoint 后同进程配对评估（07-29 教训：跨进程有 +0.0126 漂移，必须同进程）。

入口：`code/tse_qwen_sidecar_eval_a.py`（Dataset-A 评估专用，与训练隔离）
- baseline = 冻结 Qwen 主线 CER 0.343（transcribe 累计池）
- **GO 门槛**：ΔCER ≤ −0.05（同 TSE Phase-2 门槛），bootstrap 95% CI 上界 <0
- GO → 集成进提交候选；NO-GO → TSE 路径彻底封顶，转 Whisper-Sidecar 或收尾答辩

## 七、风险与红线

**红线**：
- Dataset-A 绝不进训练/选模（`tse_qwen_sidecar_train.py` 已硬校验）
- 训练产物固化进权重，推理零外部依赖（CosyVoice 只用于造数据，不进推理链）
- speaker-disjoint train/val
- 大批量合成 wav 不入 git（保文本+种子可重生）

- CosyVoice 部署受阻 → 切 GPT-SoVITS（MIT）

- 声纹克隆质量不足 → 人耳验 + 多 prompt 抽样
