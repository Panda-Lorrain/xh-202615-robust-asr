# POC A：LLM 凭内容识别家居指令的判别力验证（设计与方法）

> **日期**：2026-07-14
> **归属**：新架构"多声纹 → 多路转写 → LLM 路由挑家居指令段"的根基验证（[[multi-voice-llm-routing-architecture]]）
> **状态**：方法论完成 + 测试集构造完成 + 对抗审查完成；**结果待 llm_reject 跑完补入第 7 节**

---

## 1. 目标

新架构把"判断谁是 target"从**声纹 argmax** 换成 **LLM 凭内容识别家居指令**（绕过 enrollment 污染 → argmax 选错 target，复用 `code/llm_reject.py`）。其可靠性根基是：**LLM 能否准确区分"家居指令(accept)" vs "非家居指令(reject)"的纯文本**。

POC A 用零模型成本（不跑 diar/ASR，只跑 LLM 文本判断）验证这个判别力，决定是否启动 POC B（端到端全 speaker 转写 + llm_reject 挑，要跑模型）。

## 2. ⚠️ 防循环论证（方法论核心）

`llm_reject`（Qwen2.5-3B-Instruct）内部判断逻辑就是「家电实体 + 控制动作 + 参数合理性 + 对象合理性」CoT（`llm_reject.py:42` SYSTEM_PROMPT）。

**陷阱**：若负例也用"不含家电词"筛 → 用"无家电词"筛负例，再用"有无家电词"判 → **同义反复**，precision 虚高 0.99，结论无效。

**破法**：负例集必须**含 e 对抗层（含家电词但非指令）**：
- "空调调到四十度"（参数越界）
- "你家空调什么牌子"（闲聊提及家电）
- "空调已经在制热了"（非控制陈述）
- "空调怎么拆开"（疑问求助）

LLM 必须靠"指令性/参数/对象"判断而非"有无家电词"才能 reject 这些。**e 层的 reject 率 = LLM 是否超越关键词匹配的直接度量**。

## 3. 测试集构造（`code/build_llm_testset.py`，400 条，seed=42 可复现）

| 类 | gold | n | 来源 |
|---|---|---|---|
| 正例 pos | accept | 200 | `pos.ref` 家电类型分层抽样（空调/灯/窗帘/音乐/新风…） |
| a 干扰人新闻话 | reject | 60 | `vanilla_text`，多 speaker + 无家电无动作 + CER>1 + len>3（真实干扰人话） |
| b 乱码语气词 | reject | 40 | `vanilla_text`，≤3 字或中文占比<0.3（真实碎片） |
| c 英文水印 | reject | 25 | `dicow_text` 英文为主（vanilla 英文仅 6 不够；dicow 英文幻觉 18.8%） |
| d 空转写 | reject | 25 | `dicow_text` 空（vanilla 空仅 2 不够） |
| **e 对抗（含家电词非指令）** | reject | 50 | 硬编码 4 子类（参数越界 13 / 闲聊 13 / 陈述 12 / 疑问 12） |

**正例清洗**：`pos.ref` 31%（425/1364）是意图/闲聊/查询等非直接控制指令（[[pos-ref-not-pure-commands]]）。正例只取"含家电词或动作词"的 939 条干净池抽 200，保证 gold 无争议。防循环论证不靠此筛选（正例和 e 负例都含家电词）——靠 e 层。

## 4. 对抗审查结论（workflow `wqgwv2m65`，3 agent 并行）

**396 条审查仅 6 条争议（98.5% 干净）**：
- **a 层 58 条 + b/c/d 90 条：零争议**，gold 全部正确
- **pos 层 4 条漏网**（"全屋智能…开空调啊做饭啊"描述闲聊 / "羊绒大衣应该用什么清洗模式"疑问 / "我要开始烹饪"意图陈述 / "窗帘下架"疑 ASR 噪声）→ 清洗规则"含词"漏网，分析时 corrected_gold=reject
- **e 层 2 条弱争议**（"三十小时闹钟"时间无硬上限 / "风扇摇头怎么关掉"属可控功能）→ 保守保留 reject，原标站得住

## 6. pos.ref 非纯指令发现（副产品，[[pos-ref-not-pure-commands]]）

`pos.ref` 31% 不含家电/动作词，跨"意图指令（我要做饭）/闲聊查询（权志龙专辑）/唤醒词重复"光谱。影响：①CER 含 ref 噪声成分 ②标注 v2 复核 ③新架构 LLM 对无家电词意图指令的识别是开放问题。

## 7. 结果（2026-07-14）

**执行**：`pocA_fast_eval.py`（batch=1 符合主办方位，max_new=64，150 子集，4060 ~7min）。⚠️ 原逐条 max_new=160 + 长 SYSTEM_PROMPT 400 条要 30-50min 太慢 → 试 batch=4 实测仍 6s/条（4060 显存带宽饱和无并行收益）→ 终用 batch=1+max_new=64+规模 150。prompt 迭代 v1→v2。

**v1（原 prompt）vs v2（放宽参数审查）**：

| 指标 | v1 | v2 | 阈值 |
|---|---|---|---|
| 家居 recall | 0.25 | **0.75** | ≥0.90 |
| 非家居 recall | 0.99 | 0.97 | ≥0.85 ✓ |
| e 层 reject 率 | 0.98 | 0.94 | 防循环论证 ✓ |
| accuracy | 0.75 | 0.90 | — |
| 家居 F1 | 0.39 | 0.83 | — |

**v1 过严根因**：SYSTEM_PROMPT 第3条"参数合理性"+few-shot 全是长完整指令，LLM 把"空调十六度""风速自动""播放绝句唐杜甫"以"参数不合理/缺房间/缺值"误拒。

**v2 修复**：参数默认合理只拒荒谬（温度>40度/>100%/闹钟≤0或>24h）+短指令省略合法+播放任意内容合法。家居 recall 0.25→0.75。

**v2 剩余 12 条误拒**（Qwen2.5-3B 能力边界，非 prompt 能根治）：家电实体识别不全（"清香烟机"/"智控温"/"勃朗烤箱"/"ECO模式"/"睡眠"/"节能"）+仍要求房间（"关下空调"）+播放频道类（"讲古风音乐频道"）。prompt v3 可改但有 in-sample 过拟合风险。

**核心结论**：**LLM 判别家居 vs 非家居的逻辑根基成立**（e 层 0.94 懂"含家电词非指令要拒"+非家居 0.97 拒干扰准+家居 precision 0.92）。家居 recall 0.75 是 Qwen2.5-3B 对口语化/品牌/模式指令的能力边界。

## 8. go/no-go 标准 + POC B 预备

**实际结论（2026-07-14 用户决策）**：v2 家居 recall 0.75（<0.90 原阈值）→ **条件 GO POC B**（非纯 GO 也非 NO-GO）。理由：①LLM 判别逻辑成立（e 0.94/非家居 0.97/precision 0.92）②recall 0.75 略优于 argmax 选对 66.7%（spk-oracle-poc 死区数据）③LLM 路由真正价值=救 argmax 选错 33% 那部分（凭内容挑对 target 段）+非家居 precision 0.97 拒干扰段准 ④净 CER 靠端到端验，不依赖 prompt 小集 in-sample ⑤prompt 保持 v2（不追 v3 in-sample 过拟合）。**原阈值 recall≥0.90 设过严**——对手是 argmax（66.7% 选对）不是完美识别。

**POC B 工程入口已核查**（`enroll_infer.py`）：
- `:228-229` speakers + per_spk timeline 现成
- `:236-246` 每 speaker spk_embs 现成
- `:267-282` vanilla 路径 `cut_target_timeline(audio, per_spk[target_idx])` → generate 转写 = **改动点**（改成对每个 speaker 各切各转）
- **显存注意**：Whisper + Qwen2.5-3B 双模型同 4060 8GB 紧张 → llm_reject 走离线后处理（enroll_infer 存全 speaker 切片+文本，末尾 subprocess 批量判，仿 qwen_asr_backend 独立进程）
- **评估**：多 speaker 失败条 ~543 条，对比 argmax CER 0.67 → multi-voice CER，对照 oracle 0.607（作弊全 speaker 转写挑对）

**诚实边界**：oracle 0.607 仍不及格、是死区 60 条历史数据。新架构吃"选错 target 漏转"部分（Δ 向 0.18 靠），救不了"选对但 babble 毁 mel"（归转写器换型 Qwen3-ASR/FireRedASR）。
