# Session 经验总结：多声纹 LLM 路由验证 + content_gate v2（2026-07-14~15）

> 本 session 从接手"多声纹→LLM 路由"新架构 POC，到全链验证、content_gate v2 集成、后端差异发现。记录可复用经验教训，供后续 session/答辩归因参考。

## 核心教训（按重要性）

### 1. 小样本"证伪/证实"结论必须全量验证
POC B 30 条时判"证伪"（纠结 29 all_reject = 挑不到 target），用户要求全量死区 126 条确认后**反转**——拒幻觉有真实 CER 价值（argmax 2.34→mv 0.99，改善 126/126，全量仅死区 0.595→0.476）。
**教训**：<30 样本的方向性判断（尤其"证伪"）不可靠，必须全量确认。`all_reject` ≠ 无价值——拒幻觉在累计池 CER 是收益（幻觉 CER 2-10→拒 1.0，pos 允许拒无额外惩罚）。

### 2. 优化非普适——分后端独立验证
content_gate v2（幻觉检测+digit_postproc）对 vanilla ΔCER-0.0406 改善，对 qwen Δ+0.024 **恶化**（qwen 鲁棒死区少 0.459 + 指令多样含内容名/品牌误拒 19>拒幻觉 16）。
**教训**：任何拒识/归一优化必须在所有后端（vanilla/qwen/firered）独立验证，不能假设普适。后端特性差异（vanilla 幻觉多 vs qwen 鲁棒）决定优化方向。

### 3. 提交归一要全覆盖官方 normalize
digit_postproc 漏时间/小数（14.55 未归一致 cmd_322 假阳性）+ qwen 输出含标点（，。致 len>22 误判超长）。
**教训**：提交归一必须对齐官方 normalize（NFKC + 标点 + 数字 + 时间 + 繁简）全覆盖。任何缺口→CER 假阳性/假阴性 + 拒识误伤。规则判别前先 normalize（去标点）。

### 4. 死区是物理地板——三重坐实
spk-oracle（声纹层）+ content_gate/multi-voice（内容层）+ 幻觉检测（规则层）都救不了 babble 毁 mel 的切片。
**教训**：死区（sim<0.2，~30%）是 babble 毁 mel 物理极限，突破靠转写器换型（Qwen3-ASR 死区 0.459）或端到端，**不靠后处理**。不要在后处理上死磕死区。

### 5. 方法价值域要避开失效域（multi-voice 死结）
multi-voice 多路转写的价值域（argmax 选错条 = 切片质量差条）= 它的失效域（LLM 挑不到 target）。
**教训**：设计方法前想清"它在哪些条有价值"——如果价值域 = 失效域，方法注定失败。

### 6. batch=1 是主办方位，效率优化不靠 batch
batch=4 在 4060 无并行收益（显存带宽饱和，6s/条同逐条）+ 主办方 batch=1 测效率。
**教训**：效率优化按 batch=1（模型量化/蒸馏/更小模型），不靠 batch 掩盖 RTF。

### 7. 长 prompt LLM 评测慢——减规模 + 缩 max_new + -u
llm_reject 长 SYSTEM_PROMPT（~800 字）逐条 generate 6s，400 条 30-50min + stdout 块缓冲看不到进度（盲等）。
**教训**：LLM 评测用 max_new=64（verdict JSON 够）+ 减规模（分层抽样 150）+ python -u（实时进度）+ Monitor 监听完成事件。

### 8. 对抗审查 workflow 定位误伤 + 可抓性
2-agent 审查 hal_positives（29 抓的：26 真幻觉 + 3 误伤，定位数字格式 bug）+ 分类 deadzone_missed（113 漏的：新闻话 36/碎片 14/乱码非循环 57 地板/英文 6，规则可抓 39%）。
**教训**：规则/阈值设计后用 agent 对抗审查——独立定位误伤（gold 验证）+ 评估漏的可抓性（规则 vs LLM 地板）。比人工逐条高效且独立。

## 方法学沉淀
- **POC 阶段**：先离线（用现有数据）再跑模型；先小样本看趋势再全量确认；证伪/证实都要全量坐实。
- **集成阶段**：分后端验证 + hold-out（uid md5 分割）防过拟合 + 对抗审查定位边界。
- **诚实归因**：每步 CER 变化要能解释（哪类条改善/恶化），不报虚高口径（transcribe 不拒 vs 含拒提交要分清）。
