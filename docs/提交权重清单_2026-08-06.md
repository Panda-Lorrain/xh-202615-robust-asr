## 2. 双 venv 架构（部署关键，勿只建一个 venv）

```
code/.venv          ← 主进程: enroll_infer(diar/wespeaker/fe) + scene_route(SepFormer + 内容选路 + text_utils) + 评测
                      装 requirements.txt + speechbrain + onnxruntime
code/.venv_qwen     ← 仅 Qwen3-ASR 转写子进程(PY_QWEN, scene_route_backend.py:28)
                      只装 qwen-asr + torch(cu124)
```
- 为什么两个 venv：Qwen3-ASR 走独立 `qwen-asr` 包 + 特定 GPU torch，与主 venv 的 speechbrain/DiariZen 依赖树隔离，避免 numpy/transformers 版本冲突（曾出 `.venv_qwen` 单独跑 enroll_infer 崩 numpy2.x）。
- **SepFormer 在主 `.venv`，不在 `.venv_qwen`**——scene_route 的分离/选路在主进程做，只有最终 Qwen3-ASR 转写那一步 subprocess 进 `.venv_qwen`。
- `code/deploy_3090.sh` step1 建主 venv、step3 建 `.venv_qwen`，幂等。**主办方复现务必跑 `deploy_3090.sh`，不要只手动 `uv pip install -r requirements.txt` 进一个 venv**（scene_route 子进程会因缺 `.venv_qwen` 崩）。
